# 独立站
独立站是我们开发根据市场的需求联合ui制作的门户网站,担任展示品牌,售卖商品的功能
我们独立站搭载在shopify的平台之上,shopify一个低代码的编辑平台,所谓低代码就是我们编写代码以便市场能够根据我们提供的一些参数,让市场能够调整页面,比如我们把组件的宽高使用shopify提供的工具拆离出来,那么市场就能自己根据需求调整宽高等等.

### 开发规范
1. 没有完全的把握之前,不要动旧的代码
2. main分支始终要同步线上的live的页面每次开发前使用shopify theme pull拉取云端代码,然后提交git,提交信息里最好标识,干了什么,以及拉取的时间
3. 每次开发新功能都git另起一个分支,同时使用shopify的CLI工具创建一个新的theme,
   ![[sources/Pasted image 20260427145715.png]]
   另起的theme会出现在这里
   ![[sources/Pasted image 20260427145748.png]]
   然后市场通过审核后,他们自己上线
4. 我们开发新功能一定要在live基础之上开发,如果要上线live,注意把分支代码合并到main分支,因为有时候有些小的需求可能直接就在main上直接修改了,比如
   ![[sources/Pasted image 20260427150430.png]]
5. 不要回退到以前的旧的版本,可能有些bug改了,那么什么时候需要回退旧版本呢,如果当前的功能有问题,那么正好可以回退版本,之前开发新功能有建立分支,正好直接回退到直接可用的版本
6. 尽量不要把函数声明到全局,就算要声明到全局也使用一个类把函数包起来比如
``` JavaScript
  /**
   * Storefront API 请求类
   */
  class StorefrontAPI {
    constructor(config) {
      this.config = config;
    }
    /**
     * 执行 GraphQL 查询或 mutation
     * 
     * @param {string} query - GraphQL 查询字符串
     * @param {Object} variables - GraphQL 变量对象
     * @returns {Promise<Object>} API 响应数据
     * @throws {Error} 当请求失败或返回错误时抛出异常
     */
    async query(query, variables = {}) {
      try {
        const response = await fetch(this.config.apiUrl, {
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            'X-Shopify-Storefront-Access-Token': this.config.accessToken,
          },
          body: JSON.stringify({ 
            query, 
            variables 
          })
        });
        // 检查 HTTP 响应状态
        if (!response.ok) {
          throw new Error(`HTTP Error: ${response.status} ${response.statusText}`);
        }
        const result = await response.json();
        // 检查 GraphQL 错误
        if (result.errors && result.errors.length > 0) {
          console.error('GraphQL Errors:', result.errors);
          throw new Error(`GraphQL Error: ${result.errors[0].message}`);
        }
        return result;
      } catch (error) {
        console.error('Storefront API Request Failed:', {
          query: query.slice(0, 100) + '...', // 只显示前100字符
          variables,
          error: error.message
        });
        throw error;
      }
    }
  }

  // ===== 创建全局实例 =====
  window.StorefrontAPI = new StorefrontAPI(STOREFRONT_CONFIG);
```

# LOOI Admin 项目
## 一、项目概述

### 1.1 项目简介

LOOI Admin 是一个企业内部管理系统，用于管理 LOOI 机器人平台的应用配置、行为编辑、国际化等核心功能。

这个项目重点在于使用ai,毕竟是一个管理后台,注意一定要看一遍ai的代码,对于旧的功能迁移,强调千万不要新建数据库,可能会影响到旧的功能的使用,还要注意代码的模块化,封装解耦,这样方便ai自己读取上下文,也方便我们自己管理

**项目地址**：`https://gitee.com/tangiblefuture/looi-admin.git`

## 三、模块说明

### 3.1 IAM 模块 (身份认证)

**包路径**：`com.looi.server.modules.iam`

**功能**：用户管理、角色管理、菜单管理、字典管理

**核心表**：
- `sys_user` - 系统用户
- `sys_role` - 角色
- `sys_menu` - 菜单/权限
- `sys_dict` / `sys_dict_item` - 字典

### 3.2 I18N 模块 (国际化)

**包路径**：`com.looi.server.modules.i18n`

**功能**：多语言支持、文本管理、导入导出

**核心表**：
- `i18n_language` - 语言
- `i18n_text` - 文本
- `i18n_text_value` - 文本值

### 3.3 APP 模块 (应用管理)

**包路径**：`com.looi.server.modules.app`

**功能**：应用管理、动作序列、动作配置、表情交互、行为管理

**核心表**：
- `app_application` - 应用
- `app_menu` - 多级菜单
- `action_sequence` - 动作序列
- `action_config` - 动作配置
- `emotion_emotion` - 表情
- `behavior_behavior` - 行为
- `behavior_group` - 分段行为

#### 4.4.1 状态定义

| status | 名称 | 说明 |
|--------|------|------|
| 1 | 设计中 | 正在编辑 |
| 2 | 待定 | 暂停 |
| 3 | 延期处理 | 延后 |
| 4 | 已完成 | 可提交审核 |
| 5 | 待验收 | 等待验收 |
| 6 | 需要修改 | 审核驳回 |
| 8 | 已发布 | 正式上线 |

#### 4.4.2 类型定义

| type | 名称 | 说明 |
|------|------|------|
| 0 | 行为元素 | 正常行为 |
| 1 | 分段行为 | 分段组合 |
| 2 | 测试态 | 仅测试使用 |

#### 4.4.3 审核流程

```
设计中(1) → 已完成(4) → 待验收(5) → 已发布(8)
    ↓              ↓
 type=2       审核驳回(6) → 返回设计中(1)
(测试态)
```

#### 4.4.4 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/admin/app/behaviors/pending` | GET | 获取待审核列表 (status=4) |

| `/admin/app/behaviors/{id}/test` | DELETE | 退出测试态 |
| `/admin/app/behaviors/audit` | POST | 审核行为 |

### 4.5 行为组同步

**前端界面**：

- 已同步时按钮禁用
