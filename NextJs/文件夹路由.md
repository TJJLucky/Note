在 **Next.js** 中，**文件夹路由（File-based Routing）** 是其核心特性之一，它允许你**通过项目中的文件和目录结构自动创建页面路由（URL 路径）**，无需手动配置路由表。

从 Next.js 13 开始，官方主推 **App Router**（基于 React Server Components），同时仍支持旧的 **Pages Router**。下面重点介绍 **App Router 下的文件夹路由机制**（推荐使用）。

---

## 📁 一、基础：App Router 的目录结构

启用 App Router 需在项目根目录创建 `app/` 文件夹：

```
my-app/
├── app/                ← 路由入口（App Router）
│   ├── layout.tsx      ← 根布局（可选）
│   ├── page.tsx        ← 首页 → /
│   ├── about/
│   │   └── page.tsx    ← /about
│   └── blog/
│       └── [slug]/
│           └── page.tsx ← /blog/hello（动态路由）
├── public/             ← 静态资源
└── package.json
```

> ✅ **规则：每个路由必须包含一个 `page.tsx`（或 `.js`）文件**

---

## 🔑 二、核心路由规则

### 1. **静态路由（Static Routes）**

文件路径直接映射为 URL：

| 文件路径                         | 对应 URL           |
| ---------------------------- | ---------------- |
| `app/page.tsx`               | `/`              |
| `app/about/page.tsx`         | `/about`         |
| `app/products/list/page.tsx` | `/products/list` |

> 💡 文件夹名 = URL 路径段，`page.tsx` 是该路径的“页面组件”。

---

### 2. **动态路由（Dynamic Routes）**

用 **方括号 `[param]`** 定义动态段：

```bash
app/user/[id]/page.tsx   → 匹配 /user/123, /user/abc
```

在组件中获取参数：

```tsx
// app/user/[id]/page.tsx
export default function UserPage({ params }: { params: { id: string } }) {
  return <h1>User ID: {params.id}</h1>;
}
```

#### 多参数示例：

```
app/shop/[category]/[product]/page.tsx
→ /shop/electronics/phone
→ params = { category: 'electronics', product: 'phone' }
```

---

### 3. **Catch-all 路由（捕获所有路径）**

- **非空匹配**：`[...slug]`
    
    ```bash
    app/post/[...slug]/page.tsx
    ```
    
    - `/post/a` → `params.slug = ['a']`
    - `/post/a/b/c` → `params.slug = ['a', 'b', 'c']`
- **可选匹配（包括空）**：`[[...slug]]`
    
    - `/post` → `params.slug = undefined`
    - `/post/hello` → `params.slug = ['hello']`

> ⚠️ 注意：Catch-all 必须是路径的最后一段。

---

## 🧱 三、特殊文件（增强路由功能）

Next.js App Router 支持多种**约定式文件名**，用于扩展路由行为：

| 文件名             | 作用                         | 示例             |
| --------------- | -------------------------- | -------------- |
| `layout.tsx`    | **共享布局**（嵌套 UI）            | 导航栏、页脚         |
| `loading.tsx`   | **加载状态**（自动包裹 Suspense）    | 骨架屏            |
| `error.tsx`     | **错误边界**（捕获子树错误）           | 错误提示页          |
| `not-found.tsx` | **404 页面**                 | 自定义未找到页面       |
| `route.ts`      | **API 路由**（替代 `pages/api`） | 处理 POST/GET 请求 |

### 示例：带布局和加载状态的博客

```
app/blog/
├── layout.tsx      → 所有 /blog/* 共享的侧边栏
├── loading.tsx     → 加载时显示骨架屏
├── not-found.tsx   → 博客文章不存在时显示
├── page.tsx        → /blog 列表页
└── [slug]/
    ├── loading.tsx → 单篇文章加载状态
    └── page.tsx    → /blog/hello-world
```

## 🔄 四、路由组（Route Groups）— 不影响 URL

用 **圆括号 `( )`** 创建逻辑分组，**不会出现在 URL 中**：

```bash
app/
├── (marketing)/
│   ├── page.tsx        → /
│   └── about/page.tsx  → /about
└── (dashboard)/
    └── settings/page.tsx → /settings
```

### 用途：

- 为不同路由组应用**不同根布局**
- 实现**权限隔离**（如游客 vs 管理员）
- 组织代码结构，不影响最终 URL

---

## 🧩 五、并行路由（Parallel Routes）— 高级用法

通过 `@folder` 语法在同一层级渲染多个独立 UI 区域（如模态框）：

```
app/
├── @modal/             ← 模态框区域
│   └── default.tsx     → 默认空内容
├── layout.tsx          ← 使用 <slot> 和 <modal> 并行渲染
└── settings/
    └── page.tsx        → 主内容
```

> 适用于复杂交互场景（如 `/settings?modal=profile`）。

---

## ⚙️ 六、与 Pages Router 的区别（简要）

|特性|App Router (`app/`)|Pages Router (`pages/`)|
|---|---|---|
|路由文件|`page.tsx`|`*.tsx`（文件名即路径）|
|布局|`layout.tsx`（嵌套继承）|通过 `_app.tsx` 全局布局|
|数据获取|在组件内直接 `async/await`|需 `getStaticProps` / `getServerSideProps`|
|组件类型|默认服务端组件（零客户端 JS）|全是客户端组件（除非 SSR）|
|API 路由|`route.ts`（在 `app/` 内）|`pages/api/`|

> ✅ **新项目强烈推荐使用 App Router**

---

## ✅ 最佳实践建议

1. **优先使用 App Router**（Next.js 官方未来方向）
2. **合理拆分 layout**：避免重复代码
3. **动态路由命名清晰**：如 `[userId]` 比 `[id]` 更语义化
4. **配合 loading/error 文件**：提升用户体验
5. **用路由组管理权限页面**：如 `(auth)/dashboard`, `(public)/login`

---

## 🎯 总结

> **Next.js 的文件夹路由 = “文件系统即路由配置”**  
> 通过 `app/` 目录下的文件结构，你可以：
> 
> - 自动生成静态/动态路由
> - 嵌套共享布局
> - 添加加载、错误、404 状态
> - 实现高级路由模式（组、并行等）

这种**约定优于配置**的设计，极大简化了路由管理，是构建高性能、可维护的 Next.js 应用的基础。
